## Mac发布版实测

使用本次生成的720×480合成PNG，无私人图片。四张原图各1,383,053字节；用SHA256验证覆盖和取消结果。

| 场景 | 结果 |
| --- | --- |
| 启动默认关闭开关，导入三张图片 | 全部停在待开始；未自动上传 |
| 开启自动压缩 | 三张立即处理，实际上传进度显示99%，行背景与底部进度线同步推进；完成后填满 |
| 开启时再添加`late-auto.png` | 自动上传并完成，无需点击开始 |
| 单张覆盖第一次取消 | 四张原图摘要全部不变 |
| 同一图片再次点击覆盖 | 再次弹出原生确认面板，明确原图路径及不可撤销；确认后只替换对应原图 |
| 已完成图片在外部被修改后批量覆盖 | 该项显示“原图已被修改，请重新导入并压缩后再覆盖”，修改后的内容保留 |
| 批量覆盖取消 | 所有文件摘要不变 |
| 再次批量覆盖确认 | 提示覆盖3张，跳过已覆盖项；最终2张成功、1张因原图变更失败 |
| 覆盖后保存副本 | 默认名`auto.min.png`；副本与压缩结果逐字节相同 |
| 600px窄窗口 | 顶部开关、行内保存/覆盖、底部四个按钮均在窗口内；列表可滚动 |
| 文件结果 | PNG格式、720×480尺寸保留；覆盖成功的图片约51.7kB；无遗留覆盖暂存文件 |
| 退出后启动交付目录中的App | 空列表、自动压缩关闭；新隐私提示、批量覆盖按钮可见 |

本机截图与摘要证据（`mac-start.png`、`mac-completed.png`、`mac-single-confirm.png`、`mac-batch-confirm.png`、`mac-batch-result.png`、`mac-narrow.png` 及取消前后摘要JSON）只保存在本地，不随仓库发布。确认面板绑定主窗口，避免独立弹窗落在后台。
